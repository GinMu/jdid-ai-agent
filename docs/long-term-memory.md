# 用户长期记忆:现状与优化空间

这份文档讨论**跨会话的用户记忆**:记住用户是谁、习惯用什么、上次查到哪。
公共资料(方法规范)已由 `knowledge/` 负责,不在这里讨论。

> 结论先行:**当前完全没有做**。现在只有"会话内的短期记忆"(`MemorySaver`)和"公共知识库 RAG",
> 没有任何按用户维度持久化的记忆。本文列出成熟策略与可分阶段落地的优化。

## 1. 先把三类记忆分清

| 类型 | 含义 | 钱包里的例子 | 本项目现状 |
| --- | --- | --- | --- |
| 语义记忆 | 稳定的用户事实与偏好 | "默认身份是 Base1"、"偏好中文回答" | 未做 |
| 情景记忆 | 过去发生过什么 | "上周查过 `did:swtc:jPAF…` 的凭证" | 未做 |
| 程序记忆 | 用户的习惯与流程 | "每次都要先列凭证再逐张验证" | 未做 |
| 短期记忆 | 本次会话上下文 | 本轮工具结果 | 已做(`docs/memory.md`) |
| 公共知识 | 与用户无关的客观资料 | did:swtc / did:ethr 方法规范 | 已做(`knowledge/`) |

关键区别:公共知识可以随仓提交;用户记忆**必须按用户隔离、可删除、默认不出设备**。

## 2. 当前项目做了什么

| 事项 | 状态 | 证据 |
| --- | --- | --- |
| 用户画像/偏好 | 未做 | 服务端没有 `user_id` 概念,`session_id` 只用于图状态 |
| 情景记忆检索 | 未做 | 无历史对话入库 |
| 记忆的读写接口 | 未做 | 没有"查看/删除我的记忆"入口 |
| 可复用的检索设施 | 已有 | `knowledge.py` 的 BM25 可以原样用于情景记忆 |
| 可承载本地存储的位置 | 已有(钱包侧) | `SessionStore`(`KeyValueStore` 之上的键值存储) |

所以现在的处境是:**每一轮都是"陌生人 + 一堆工具"**,用户每次都要重新说清楚要查哪个 DID。

## 3. 成熟策略

| 编号 | 策略 | 代表实现 | 机制 | 优点 | 局限 |
| --- | --- | --- | --- | --- | --- |
| L-A | 显式偏好 KV | 自建 profile 表 | 用户/系统显式写入 `{key: value}` | 极稳、可解释、可编辑 | 只能覆盖已知维度 |
| L-B | 情景记忆检索 | [mem0](https://github.com/mem0ai/mem0) | 对话切片入库,按 query 召回 | 上下文恒定,细节不丢 | 召回质量决定体验 |
| L-C | 时序知识图谱 | [Graphiti / Zep](https://github.com/getzep/graphiti) | 实体+关系+有效期,冲突可解 | 能处理"上个月那个人是谁" | 工程重,依赖抽取质量 |
| L-D | 分层记忆 | [MemGPT / Letta](https://github.com/letta-ai/letta) | core / recall / archival 分级换页 | 长任务最强 | 复杂、调用多 |
| L-E | 活动日志聚合 | 自建 | 记录事件,按规则聚合成"常用 X" | 无需模型,可审计 | 规则要维护 |
| L-F | 记忆管理 UI | ChatGPT Memory / 各家"记忆"页 | 用户可查看、编辑、删除记忆 | 合规与信任的必需品 | 需要产品界面 |

### 每种策略最容易被忽略的前提

| 策略 | 前提 | 不做会怎样 |
| --- | --- | --- |
| L-A | 明确"哪些键允许写" | 变成任意 KV,污染与隐私都失控 |
| L-B | 入库前做**写入过滤** | 噪音进库,召回全是废话 |
| L-C | 冲突消解规则(时间/来源优先级) | 同一事实两个版本并存,回答自相矛盾 |
| L-E | 衰减与上限 | 日志无限增长,聚合结果越来越糊 |

## 4. 钱包场景值得记什么(按价值排序)

| 优先级 | 记忆项 | 类型 | 存哪 | 说明 |
| --- | --- | --- | --- | --- |
| P0 | 默认身份 DID / 地址 | 语义 | **钱包本地** | 用户不必每次说"查我自己的" |
| P0 | 常用查询过的 DID(最近 N 个) | 情景 | 钱包本地 | "再看下上次那个 DID" |
| P1 | 已验证凭证的结论缓存(含过期时间) | 语义 | 钱包本地 | 避免重复 `verify_credential`;**必须带 TTL** |
| P1 | 拒绝过的提案类型 | 语义 | 钱包本地 | 安全偏好,例如"从不签消息" |
| P2 | 回答风格偏好(简洁/详细) | 语义 | 钱包本地 | 影响 system prompt |
| 禁止 | 私钥、助记词、凭证原文、精确金额 | — | **哪里都不存** | 与现有 `redact()`/摘要策略一致 |

看这条分界线:**P0/P1 全部可以留在钱包本地**,服务端只见到当轮摘要 —— 这既省了合规成本,
也让"记忆"天然具备离线可用性。

## 5. 推荐路线

| 阶段 | 做什么 | 改动 | 风险 |
| --- | --- | --- | --- |
| L1 | **本地显式偏好**(L-A):默认 DID、回答风格,存 `SessionStore` | 钱包侧加几个键 + 组装 system 附加信息 | 低 |
| L2 | **本地情景记忆**(L-B 的轻量版):最近 N 次查询过的事实/结论,本地按 BM25 召回 | 钱包侧存 + 复用服务端检索思路 | 低 |
| L3 | **记忆写入过滤 + 管理 UI**(L-F):可查看/删除 | UI + 存储 | 中 |
| L4 | 服务端权威记忆(多设备同步) | 引入 `user_id`、加密存储、删除权 | 高(先别做) |

### 为什么先做"本地"而不是"服务端记忆"

| 维度 | 本地(钱包) | 服务端 |
| --- | --- | --- |
| 隐私 | 原文不出设备,只把摘要拼进本轮请求 | 要承担存储合规与删除权 |
| 多设备 | 不同步 | 天然同步 |
| 离线 | 可用 | 不可用 |
| 实现成本 | 低(已有 `SessionStore`) | 高(账号体系、加密、审计) |

钱包的核心资产是"用户自己掌握身份",把记忆放本地与这个定位一致。

## 6. 写入过滤:什么情况下才记

三条都满足才写(避免把噪音记成偏好):

1. **稳定性**:跨会话仍然成立(默认 DID 稳定;"刚才查了什么"不算);
2. **频次**:同一事实出现 ≥2 次,或用户显式要求"记住";
3. **可撤销**:能定位到具体键并删除(不是一段无法拆解的自然语言)。

## 7. 冲突消解与过期

| 场景 | 规则 |
| --- | --- |
| 同一键被写入两次 | 后写覆盖,保留 `updatedAt` 与来源(用户显式 > 系统推断) |
| 推断与显式冲突 | **显式优先**,并给出"你之前设置过…要改吗" |
| 结论类记忆 | 必须带 `expiresAt`(如凭证验证结论),过期即视为未知 |
| 用户删除 | 立即失效,并把删除记进审计 |

## 8. 怎么验证长期记忆真的有用

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 命中率 | 应使用记忆的问题里,实际用上的比例 | > 70% |
| 误记率 | 记忆导致答错的比例 | < 2% |
| 纠正率 | 用户纠正次数 / 使用次数 | 逐周下降 |
| 删除生效 | 删除后下一次请求不再出现该记忆 | 100%(必须单测) |

## 11. 记忆怎么更新:覆盖还是冗余

一句话:**按记忆类型分别处理**,不要用一套策略套所有记忆。

| 记忆类型 | 例子 | 更新方式 | 理由 |
| --- | --- | --- | --- |
| 唯一真值(profile 键) | 默认身份、回答语言、是否允许签名 | **覆盖**(保留一份历史版本) | 同一时刻只能有一个有效值 |
| 事件(史实) | "上周查过 `did:swtc:jPAF…`"、"验证过 #2" | **只追加,不覆盖** | 事件发生过就不该消失 |
| 会过期的事实 | "凭证 #2 已验证""余额 X" | 追加 + **TTL**,过期视为未知 | 过期事实必须失效,不能当反例 |
| 推断(偏好、习惯) | "喜欢简洁回答""常用这个 DID" | **冗余多份 + 置信度衰减** | 单次推断不可靠,靠频次累积 |

### 11.1 推荐结构

```json
{
  "key": "answer_language",
  "value": "zh",
  "source": "user_explicit",
  "confidence": 1.0,
  "updatedAt": "2026-11-26T10:00:00Z",
  "expiresAt": null,
  "version": 3,
  "supersedes": "v2",
  "supersededAt": null
}
```

事件类用另一种形状(append-only):

```json
{
  "type": "credential_verified",
  "credentialId": "did:swtc:j…#vc-2",
  "result": true,
  "at": "2026-11-26T10:05:00Z",
  "expiresAt": "2026-12-03T10:05:00Z"
}
```

### 11.2 覆盖还是冗余:判断规则

| 问题 | 选覆盖 | 选冗余 |
| --- | --- | --- |
| 两个值能同时为真吗? | 不能(语言偏好) | 能(不同时间的查询) |
| 需要审计"改过什么"吗? | 需要 → 覆盖 + 版本 | — |
| 推断可靠吗? | 显式/高置信 | 低置信 → 多份 + 衰减 |
| 会过期吗? | — | 会 → 追加 + TTL |

**存储上可以冗余,读取上必须唯一**:读路径永远只取"最新、未过期、未被 superseded"的那一条。
冗余只服务于审计与回溯,不参与决策。

## 12. 旧记忆不得覆盖新要求

### 12.1 裁决顺序

```text
安全约束(P0,不可覆盖)
  > 用户当前指令
  > 用户显式设定(记忆,高置信)
  > 本次工具实测结果
  > 历史对话中的旧结论
  > 推断型记忆
```

两条反直觉但重要的规则:

1. **工具实测优于记忆**:记忆说"7 张凭证",这次读到 3 张 → 用 3 张,并**回写**记忆(缓存失效);
2. **推断永不覆盖显式**:推断"用户喜欢英文"遇到显式"以后用中文" → 显式赢。

### 12.2 冲突消解流程

```text
写入新记忆/收到新指令
  → 找出同 key 的旧记忆
      ├─ 值相同:只更新 updatedAt
      ├─ 值不同且新值来自显式:旧值 supersededAt = now,新值 version+1
      └─ 值不同但新值来自推断:不覆盖显式;若是推断覆盖推断,按置信度取高者,低者置 superseded
  → 读路径过滤:supersededAt != null 或已过期 → 不参与上下文
  → 冲突若涉及"当前指令",在回答里提一句"已按你最新的要求处理"
```

### 12.3 结构上避免"旧压新"

| 手段 | 说明 |
| --- | --- |
| 记忆放**数据区**,不放 system 区 | 顺序本身就传递权重(见 `docs/memory.md` 9.4) |
| 冲突记忆**不进**本轮上下文 | 只"优先用新的"不够,旧值留在上下文仍会带偏模型 |
| 每次引用记忆前自检 | 与最后一条用户指令是否冲突;冲突则不引用 |
| 失效标记而非删除 | `supersededAt` 便于审计"什么时候改的" |
| 显式撤销 | 用户说"忘掉" → tombstone,后续不再出现 |

### 12.4 用户可见行为

| 场景 | 期望表现 |
| --- | --- |
| 用户改动偏好 | 立即生效;回复里可轻描淡写提一句"已改为…" |
| 记忆与本次要求冲突 | 按本次要求;必要时说明"之前设置过 X,已按新的处理" |
| 用户问"你记得我什么" | 列出 P0/P1 记忆并允许删除(见 L-F) |
| 记忆过期 | 不说"已验证",而是重新验证 |

## 13. 测试(实现时必须覆盖)

| 用例 | 断言 |
| --- | --- |
| 覆盖 | 同 key 显式写入新值 → 旧值 `supersededAt` 非空、读路径只返回新值 |
| 冗余不参与决策 | 存储里两条事件并存,读路径只取最新未过期 |
| 推断不覆盖显式 | 推断与显式冲突 → 显式生效,推断被标记 |
| 实测回写 | 工具结果与记忆不一致 → 更新记忆并记录 `source=tool_result` |
| 过期失效 | `expiresAt` 已过 → 不参与上下文,回答重新验证 |
| 撤销 | tombstone 后不出现,且审计留痕 |
| 冲突不入上下文 | 冲突记忆不出现在本轮 prompt(可用字符串断言) |

这些用例与 [`docs/memory.md`](memory.md) 第 10 节(冲突与预算)是同一套规则的两种视角:
那边管"放不下时删谁",这边管"冲突时信谁"。
